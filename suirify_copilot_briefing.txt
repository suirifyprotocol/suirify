1. The Story — Why This Exists
Nigeria has over 100 million people who interact with digital services every day. Every bank app, every crypto exchange, every government portal, every DeFi protocol that wants to onboard a Nigerian user must verify their identity. This is not optional — it is mandated by law across five simultaneous regulatory frameworks: CBN, NDPA, NITDA, SEC, and NCC.

The current system is broken in a specific and devastating way. Every single platform builds its own KYC pipeline from scratch. The same Nigerian citizen uploads their NIN to Kuda. Then to OPay. Then to Binance. Then to a DeFi protocol. Then to a government portal. The same document. The same biometrics. Over and over. Every platform stores this sensitive data on their own servers — creating hundreds of separate breach surfaces across the Nigerian digital economy.

This is not just a user experience problem. It is a compliance crisis. Platforms face penalties up to NGN 10,000,000 under NDPA for improper biometric storage. CBN fines institutions NGN 2,000,000 per KYC default. NITDA requires annual compliance reports that most platforms cannot properly generate. The entire system relies on manual spreadsheets, fragmented APIs, and annual self-reports that nobody verifies.

The Root Cause
There is no shared, reusable identity compliance infrastructure in Nigeria's digital economy. The NIMC NIN API exists. The CBN KYC rules exist. The NDPA exists. But there is no layer connecting them in a privacy-preserving, auditable, and reusable way. That layer is Suirify.

2. What Suirify Is
Suirify is Nigeria's AI-powered identity compliance infrastructure — a protocol that lets a Nigerian user verify their identity once and reuse that verification across every digital platform they will ever use, without ever re-exposing their personal data.

Think of it like this: Stripe is to payments what Suirify is to identity. Every website eventually needs a payment layer — they plug in Stripe. Every Nigerian digital service eventually needs a compliant identity layer — they will plug in Suirify.

User reuses everywhere	Any platform with Suirify SDK checks wallet for valid attestation. No re-verification needed.	CBN compliant. NDPA compliant. NITDA compliant. SEC compliant.
 
3. The Technical Architecture
Suirify has five layers. Understanding all five is essential before writing any code.

Layer	What It Does
Layer 1 — Input	React + TypeScript + Vite frontend. Collects wallet address, NIN, selfie. Handles consent signing. No PII stored here.
Layer 2 — SDK / API	@suirify/suirifysdk npm package. Read-only. Consent-first. Framework-agnostic. Methods: getAttestationForOwner(), getPublicClaims(), isValid().
Layer 3 — AI Processing (Enclave)	Node.js backend inside Azure Confidential Computing enclave. NIMC NIN API lookup. Azure Face API — biometric face match + liveness detection. PII deleted from memory immediately after use.
Layer 4 — Rules Engine	Deterministic pass/fail logic. JSON Framework Registry (CBN/NDPA/NITDA/SEC). AI explains (Azure). Rules Engine decides. Every result traceable to a regulation clause.
Layer 5 — Sui Blockchain	Suirify_Attestation object. Soul-bound, non-transferable, immutable. Contains zero PII. Permanently queryable for regulator visibility.

3.1 The AI Pipeline
This is the intelligence core of Suirify. Two Azure Face API calls + one NIMC API call. Nothing more.

1.	NIMC NIN API: Retrieves official identity record (name hash, DOB, gender, photo). Deterministic.
2.	Azure Face API — Face Match: Compares live selfie to NIMC photo. Returns confidence score (0-1). Distance threshold: 0.60.
3.	Azure Face API — Liveness Detection: Confirms user is physically present. Rejects deepfakes, printed photos, screen replays. Confidence threshold: 0.95.
4.	Rules Engine: Takes all three outputs. Makes final PASS/FAIL. Maps to framework requirements.
5.	PII Purge: NIN, selfie, DOB, name — deleted from memory. Only boolean claims written to blockchain.

3.2 The Attestation Object
This is what lives on-chain after a successful verification. It contains zero PII. It is the user's reusable compliance credential.

Suirify_Attestation {
  owner: wallet_address,         // identity anchor
  nin_verified: true,            // NIN validated against NIMC
  face_matched: true,            // Azure Face API: selfie matches NIMC photo
  liveness_passed: true,         // Azure Face API: live human confirmed
  is_over_18: true,              // calculated from NIMC DOB
  is_human_verified: true,       // all checks passed
  pii_not_stored: true,          // NDPA compliance signal
  consent_recorded: true,        // cryptographic consent signature on record
  verification_level: 2,         // CBN Tier 2
  verifier_source: 1,            // NIMC NIN API
  framework_satisfied: [         // all frameworks this attestation satisfies
    'CBN_KYC_2023',
    'NDPA_2023',
    'NITDA_COP_2022',
    'SEC_2024'
  ],
  issued_at: 1713600000000,
  expires_at: 1745136000000,     // 1 year default
  status: 'active'
}

6. The Chrome Extension — Why It Exists
Most people interact with websites and apps every day without reading a single line of the Terms & Conditions or Privacy Policy. These documents are deliberately long, complex, and written in legal language that ordinary Nigerians cannot parse. People accept them blindly. They have no idea what data is being collected, who it is shared with, or whether it violates NDPA 2023.

The Suirify Chrome Extension — Suirify Shield — solves this. When a user visits any website, the extension automatically fetches the T&C and Privacy Policy, runs it through an AI analysis against NDPA and NITDA rules, and gives the user a plain-English (or Pidgin or Yoruba) summary with a risk score and flagged clauses.

This is not a separate product. It is a natural extension of Suirify's core mission. Suirify verifies your identity. Suirify Shield verifies the internet back. Together they create the full data sovereignty stack: you control your identity, and you understand what you are consenting to.
