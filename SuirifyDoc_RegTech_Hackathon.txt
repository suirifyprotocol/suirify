The Problem: Nigeria's Identity Compliance Gap
Every Nigerian digital platform fintech, dApp, exchange, or government portal that onboards users faces a significant regulatory obligation to verify identity. This obligation is governed by five simultaneous frameworks:

•	CBN Customer Due Diligence Regulations 2023: Requires NIN, BVN, and biometrics.
•	NDPA 2023: Classifies biometrics as sensitive data, requiring minimization and non-storage.
•	NITDA Code of Practice 2022: Mandates user identity authentication.
•	SEC Digital Assets Rules 2024: Requires KYC for crypto platforms.
•	NCC Consumer Protection Regulations: Governs SIM-NIN linking.

The Gap
Currently, each organisation builds its own verification pipeline, leading to several critical issues:
•	Duplication: Every platform re-verifies the same Nigerian citizen from scratch.
•	Privacy Violations: Biometric data is stored across hundreds of separate databases.
•	Compliance Theatre: Lack of auditable evidence trails, relying on annual self-reports.
•	No Interoperability: A verified user on one platform cannot prove that verification on another.

The Root Cause
There is no shared, reusable identity compliance infrastructure in Nigeria's digital economy. While the NIMC NIN API, CBN KYC obligations, and NDPA rules exist, there is no layer connecting them in a privacy-preserving, auditable, and reusable way. Suirify is that layer.

Document 3: Workflow & User Journey
End-to-End Identity Compliance Flow
Suirify operates across three distinct journeys running in parallel to bridge Nigeria's identity compliance gap:
•	Citizen Journey: A Nigerian user verifies once and reuses that verification across the ecosystem.
•	Platform Journey: A dApp or fintech integrates the Suirify SDK to gate features and satisfy regulatory obligations.
•	Regulator Journey: Authorities like NITDA or the CBN query compliance posture on-chain in real time.

Journey 1: The Citizen (Verify Once)

1.	Connect Wallet: The user visits the Suirify portal or an integrated platform and connects a Sui-compatible wallet. This wallet address serves as the persistent identity anchor for all future attestations.
2.	NIN Submission: The user inputs their 11-digit National Identification Number (NIN). This sensitive input is routed immediately to the Suirify Enclave Backend; it never touches a standard database.
3.	Selfie Capture: The user captures a selfie via the browser. Both the image and the NIN are held only in memory within the enclave and are never written to disk.
4.	AI Verification Pipeline (inside secure enclave): (a) NIMC API Call retrieves official data (name, DOB, gender, photo) and calculates if the user is over 18. (b) Azure Face API compares the live selfie against the NIMC photo (match threshold: 0.60 cosine distance). (c) Azure Liveness Detection rejects deepfakes, screen replays, or printed photos in real time. (d) PII Deletion once the rules engine makes a decision, all PII (NIN, selfie, DOB) is permanently deleted from memory.
5.	Attestation Issuance: If all checks pass, Suirify issues a Suirify_Attestation object to the user's wallet on the Sui blockchain. This object includes boolean claims (e.g. is_over_18: true) and identifies which frameworks are satisfied (CBN, NDPA, NITDA, SEC).
6.	Reuse Anywhere: The verified attestation stays in the user's wallet. Other platforms can query this status without the user ever having to resubmit their NIN or selfie.

Journey 2: The Platform (Integrate Once)
Developers can secure their platforms in four steps:
7.	Install SDK: npm install @suirify/suirifysdk
8.	Initialize: Set up the client with the Sui RPC URL and attestation type.
9.	Handle Consent: Implement the setConsentHandler to display the consent modal to users.
10.	Gate Features: Use sdk.getPublicClaims(walletAddress) to verify age or human status before granting access.

Compliance Evidence: Every claim request generates an SDK access log. These logs containing wallet addresses and timestamps but zero PII serve as auditable evidence for CBN or NITDA reporting.

Journey 3: The Regulator (Real-Time Visibility)
Regulators move away from annual self-reports to real-time oversight using Sui chain queries or the Suirify Regulator Dashboard:
•	Total verified users across all Suirify-integrated platforms
•	Framework compliance posture per platform
•	Expired attestations requiring renewal
•	Revoked access events and fraud signals
•	Zero PII ever returned all data is anonymised aggregate signals

Document 4: Solution Architecture
Architecture Overview: Suirify is designed as a modular, five-layer identity compliance infrastructure deployed on the Sui blockchain. The architecture prioritises isolation of responsibilities, ensuring each layer performs a specific function without unnecessary data exposure.

The 5-Layer Stack
Layer	Description
Layer 1: Input Layer	User-facing entry point where wallet addresses, NIN submissions, and selfies are collected alongside cryptographic consent signatures. Built with React, TypeScript, and Vite. No PII stored or logged at this stage.
Layer 2: SDK / API Layer	Provides the @suirify/suirifysdk npm package — a read-only, consent-first, framework-agnostic interface for developers. Methods: getAttestationForOwner(), getPublicClaims(), isValid().
Layer 3: AI Processing (Enclave)	Hosted within the Suirify Enclave Backend. Handles NIMC NIN API lookups, Microsoft Azure Face API biometric matching, and Azure liveness detection to prevent anti-spoofing. PII processed ephemerally — never written to disk.
Layer 4: Rules Engine	Executes pass/fail compliance decisions using policy-as-code (OPA-style). Utilises Framework Registry JSON. Every decision logged with non-PII reason codes. AI (Azure) explains — Rules Engine decides.
Layer 5: Output Layer	Manages the on-chain Suirify_Attestation object on the Sui Blockchain. Non-transferable, immutable, auditable, and contains zero PII. Permanently queryable for regulator visibility.

Component Breakdown
1. Frontend Portal
Built using React, TypeScript, and Vite. Facilitates wallet connection, consent signing, and verification data submission. No PII stored or logged.

2. Suirify Enclave Backend
Privacy-preserving core running on Node.js and Express within a secure compute enclave. Processes NIN strings and base64 images ephemerally. Key sub-components:
•	NIMC NIN Lookup: Retrieves identity records via the developer API.
•	Azure Face API Face Match: Compares selfies against NIMC records with 0.60 cosine distance threshold.
•	Azure Face API Liveness Detection: Anti-spoofing module classifying images as real or spoofed in real time.
•	Claim Extractor: Derives boolean claims (e.g. is_over_18) before immediately deleting all PII from memory.

3. Rules Engine
Uses deterministic decision logic and a JSON framework registry. Framework adaptability requires no code rebuild — adding a new regulation means adding a new JSON entry. Every decision logged with non-PII reason codes for auditing.

4. Sui Smart Contract
Deployed on Sui Testnet. Package ID: 0x2a81ddb98779253bd431e4737caca7c29bcfa8ac8ed57eaddecaf6fc530226e2
Properties: Attestations are soul-bound (non-transferable), immutable, revocable by the issuer, and expiry-aware.

5. SDK (@suirify/suirifysdk)
TypeScript npm package serving as a read-only interface for dApps. Methods: getAttestationForOwner(), getPublicClaims(), isValid().

Document 5: Rules Engine Logic Explanation

Design Principle: AI Explains, Rules Engine Decides
Suirify operates on the core principle that while AI handles complex sensory processing, the final compliance determination is reserved for a deterministic rules engine.
•	Azure Face API: Performs biometric face match and liveness detection, outputting confidence scores.
•	Rules Engine: Executes the final pass/fail decision based on strict thresholds.
•	Traceability: Every decision is mapped to a specific regulatory source clause and threshold, ensuring no black-box compliance calls.

Document 6: AI Usage Explanation

AI Components
Suirify utilises AI at three distinct stages in the pipeline to ensure identity integrity.

1. NIMC NIN API Identity Processing
Retrieves authoritative identity records from Nigeria's national database. Serves as the foundation for document verification under CBN Reg. 1.5.3 (2023). Deterministic either the record is found or it is not.

2. Microsoft Azure Face API Biometric Face Match
Compares the live selfie against the NIMC NIN passport photo. Uses Azure's face verification model with a 0.60 cosine distance threshold. Azure Face API achieves high accuracy on diverse demographic populations including African faces. Output is a probabilistic confidence score; the Rules Engine makes the final pass/fail determination.

3. Microsoft Azure Face API Liveness Detection
Employs Microsoft Azure's liveness detection technology to prevent presentation attacks — printed photos, screen replays, and deepfake videos. Azure detects whether the selfie comes from a live, physically present person. Liveness confidence threshold: 0.95. Output is probabilistic; the Rules Engine makes the final pass/fail determination.

Why Microsoft Azure?
Microsoft Azure Face API is the AI backbone of Suirify's verification pipeline. Azure's enterprise-grade liveness detection and face matching are purpose-built for compliant identity verification at scale — making Suirify the natural RegTech infrastructure partner for Nigeria's digital economy, aligned with Microsoft's AI Skills Week mission.
