2. Backend Engineer Tasks
Stack: Node.js + Express + Secure Enclave (Azure Confidential Computing). Vector DB for verification records. No PII ever written to disk.

2.1 Enclave Backend — Core Pipeline
Task	Specification
NIN Submission Handler	Receive NIN from frontend. Route to NIMC NIN API. Extract: name_hash, DOB, photo, gender. Calculate is_over_18. Hold in memory only.
NIMC NIN API Integration	POST to NIMC developer API. Handle: found/not found. Return structured result to Rules Engine. Log non-PII event.
Azure Face API — Liveness	Create Azure liveness session. Return session token to frontend SDK. Receive liveness result. Pass confidence score to Rules Engine.
Azure Face API — Face Match	POST live selfie + NIMC photo to Azure Face verify endpoint. Return confidence score to Rules Engine. Delete both images immediately.
PII Purge	After Rules Engine decision: delete NIN string, selfie bytes, DOB, name from memory. Log purge timestamp.
Claim Extractor	From Rules Engine output, extract boolean claims: nin_verified, face_matched, liveness_passed, is_over_18, is_human_verified, pii_not_stored, consent_recorded, verification_level.

2.2 Rules Engine
Component	Specification
Input Schema	nin_api_result (found, DOB, photo_retrieved) + face_match_result (confidence, distance, threshold 0.60) + liveness_result (confidence, decision, threshold 0.95) + selected_frameworks
Decision Logic	NIN found -> PASS | face distance <= 0.60 -> PASS | liveness confidence >= 0.95 + realface -> PASS | DOB -> calculate is_over_18 | all checks PASS -> issue attestation
Framework Registry	JSON file — CBN_KYC_2023, NDPA_2023, NITDA_COP_2022, SEC_2024. Each framework defines required_claims. Engine checks claims against selected frameworks.
Failure Codes	NIN_NOT_FOUND | FACE_MATCH_FAILED | LIVENESS_FAILED | AGE_BELOW_18 | MAX_RETRIES_EXCEEDED | NIN_ALREADY_ATTESTED | CONSENT_DENIED
Audit Log	Every decision logged: event_id, wallet_address, AI confidence scores, rules engine result, error_code, frameworks_checked. Stored in Vector DB. No PII.

2.3 API Endpoints
Endpoint	Specification
POST /api/verify/start	Initiates verification session. Returns session_id and Azure liveness session token.
POST /api/verify/submit	Receives wallet_address, NIN, selfie, consent_signature, frameworks[]. Runs full pipeline. Returns attestation or error code.
GET /api/attestation/:wallet	Returns attestation object for a given wallet address (no PII, claims only).
POST /api/check-name-match	AML use case. Receives wallet_address + user-provided name. Returns {match: true/false} only.
GET /api/dashboard/compliance	Returns Compliance Officer Dashboard data for a given platform_id. All aggregate, no PII.
GET /api/dashboard/regulator	Returns Regulator SupTech Dashboard data. Ecosystem-wide aggregate. No PII.
POST /api/extension/analyze	Chrome Extension endpoint. Receives site URL + policy text. Returns AI risk analysis JSON.

3. Smart Contract Engineer Tasks
Chain: Sui Testnet. Package ID: 0x2a81ddb98779253bd431e4737caca7c29bcfa8ac8ed57eaddecaf6fc530226e2

Task	Specification
Suirify_Attestation Object	Soul-bound, non-transferable Sui object. Contains all boolean claims. Contains issued_at, expires_at, verification_level, framework_satisfied array. Zero PII on-chain.
Required Claims Schema	nin_verified | face_matched | liveness_passed | is_over_18 | is_human_verified | pii_not_stored | consent_recorded | verification_level | verifier_source
Mint Function	Called by Suirify issuer key only. Receives wallet address + claims struct. Mints attestation to wallet. Emits event.
isValid() Method	Returns true if attestation exists AND current_time < expires_at AND status != revoked.
Revocation	Issuer can revoke attestation (e.g. NIN conflict detected). Sets status to revoked. isValid() returns false immediately.
Expiry & Renewal	expires_at set at mint (default: 1 year). On expiry, isValid() returns false. User can re-verify to mint fresh attestation.
On-Chain Query for Regulator	Read-only query returning aggregate counts: total_attestations, active_count, expired_count, revoked_count, framework_breakdown. No individual wallet data exposed.
Attestation Reuse Test	Verify that a second platform querying the same wallet gets attestation status without triggering new verification. SDK getPublicClaims() must work across platforms.
